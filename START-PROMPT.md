# Промпты передачи сессии «Перелёты»

Порядок. Сессия заполнилась (сжатие, Claude переспрашивает записанное, ошибается в известном):
1. Вставить в **неё** промпт «ЗАКРЫТИЕ СЕССИИ». 2. Дождаться «ПЕРЕДАЧА ГОТОВА» с номером коммита. 3. Открыть новую сессию с репозиторием `polymercalgary/family-flight-archive`. 4. Вставить в новую сессию «НАЧАЛО СЕССИИ». После этого старая сессия ничего не пишет (CLAUDE.md §5).
Промпты постоянные; всё меняющееся лежит в STATE.md.

---

## НАЧАЛО СЕССИИ (вставить в новую сессию)

```
Это продолжение проекта «Перелёты» (история перелётов семьи 2016–2026, таблицы Google, PDF на Drive, сайт archive.billup.cloud:8443, программа flights.py). Ты продолжаешь прежние сессии Claude и должен знать всё, что знали они. Их память — репозиторий GitHub polymercalgary/family-flight-archive, ветка main.

1. Подключи репозиторий, git pull в main. Проверь, что видишь CLAUDE.md, STATE.md, FUTURE.md, START-PROMPT.md, docs/RULES.md, app/, history/.
2. Прочитай ПОЛНОСТЬЮ, по порядку: CLAUDE.md; README.md; STATE.md целиком; FUTURE.md; docs/RULES.md; конец history/ текущего месяца (последние 2 дня). Нужного факта нет — сначала поиск по репозиторию и таблицам, и только потом вопрос мне.
3. Ничего не меняй и не запускай, пока я не скажу. Ответь коротко, по-русски, простыми словами: а) последний коммит (хэш и описание); б) где сайт и какой сервер сейчас основной по STATE; в) текущий шаг (STATE 0.5); г) что решено мной и ждёт выполнения; д) что ждёт моего решения; е) правила, которые будешь соблюдать, коротко; ж) что в записях противоречиво или неясно.
4. Дальше работай по CLAUDE.md: решаю я; документ → только JSON (если я не просил иного); данные по-английски без кириллицы; секреты не показывать и не просить; серверные команды — только через согласование с сессией VPN; каждое подтверждённое изменение — сразу в STATE и журнал, commit и push в том же ответе; когда сессия заполняется — скажи и выполни «ЗАКРЫТИЕ СЕССИИ».
```

## ЗАКРЫТИЕ СЕССИИ (вставить в заполненную сессию)

```
Сессия заполняется — готовим передачу. Ничего на ПК и серверах не делай. По порядку, покажи итог:
1. git pull --rebase в main.
2. STATE.md раздел 0.5 «Текущий шаг»: где остановились (время), что я решил и не выполнено, что ждёт моего ответа, первое действие новой сессии. Устаревшее не удаляй — помечай «ЗАМЕНЕНО дата → …».
3. STATE.md: всё изменившееся за сессию — «было → стало» с датой и источником; мои решения — в раздел 3 с меткой [A дата].
4. Журнал history/<месяц>.md: итог за сегодня — сделано, решено, осталось.
5. Каждая выданная мне версия файла программы лежит в app/ и описана в STATE; README.md сверен.
6. CLAUDE.md меняй только с моего согласия: предложи правку текстом.
7. commit + push. Ответь «ПЕРЕДАЧА ГОТОВА», хэш коммита, 5–10 строк — что новая сессия должна знать первым. После этого в репозиторий больше не пиши.
```
