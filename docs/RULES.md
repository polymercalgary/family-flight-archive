# docs/RULES.md — правила данных проекта «Перелёты»

Перенесено 01.11.2026 из записей прежних сессий (память Claude, файл «family-flight-history»). Метка `[T 01.11]` = из пересказа, текущей проверкой по таблицам не подтверждено; Alex подтверждал эти правила словами в прежних сессиях. Менять — только с согласия Alex.

## 1. Люди
- Отслеживаются только: Rodionov Aleksei (бывает Alexey/Aleksey — как в документе), Rodionova Anna, Rodionova Alisa `[T 01.11]`.
- Попутчики по общей брони (другие родственники, знакомые, деловые контакты) в JSON не включаются `[T 01.11]`.
- Формат `Passenger Name`: «Фамилия Имя», Title Case. Порядок и регистр нормализуются всегда; от документа берётся только вариант написания имени `[T 01.11]`.

## 2. Колонки таблицы (A–Y) `[T 01.11]`
Category, Travel Date, Time Depart, From, To, Arrival Date, Time Arrival, Flight Number, Carrier, Duration, Original Amount, Currency, USD Value, CAD Value, Vendor/App, Issue Date, Itinerary Link, Comment, UniqueID, Passenger Name, Ticket Number, PNR, OTA Order ID, Receipt Link, Boarding Pass Link.
- Одна строка = один сегмент × один пассажир.
- `Category`: `Flight` (по умолчанию), `Flight - CANCELLED`, `Train` (только мост между двумя перелётами; также заменитель для аренды авто/автобуса — только по явной просьбе Alex и с пометкой в Comment).
- `OTA Order ID` в таблице = статус проверки имени файла: `✅ PDF Verified` / `⚠️ Manual Check Required` (пишет программа). Во входном JSON — пусто или реальный номер заказа агентства.
- `Receipt Link` — настоящая гиперссылка (rich text), не формула `=HYPERLINK()`.
- `Boarding Pass Link` не используется (очищается). `USD Value`/`CAD Value` не заполняются.
- `Comment`: `Family flight` — если пассажир Rodionova Anna или Rodionova Alisa; иначе пусто (для отменённых рейсов — старый текст об отмене). Пояснения и сомнения — в ответе в чате, не в Comment.
- `Duration` считается по часовым поясам городов (формат `Ч:ММ`), порядок поиска пояса — `app/flights.py` (v1.4).

## 3. Входной JSON (точная форма) `[T 01.11]`
Плоская структура, ключи Title Case с пробелами, как названия колонок:
```json
{
  "segments": [
    {"Travel Date": "2026-01-09", "Time Depart": "13:55", "From": "Stavropol", "To": "Moscow",
     "Arrival Date": "2026-01-09", "Time Arrival": "17:15", "Flight Number": "SU1367"}
  ],
  "passengers": [{"Passenger Name": "Rodionov Aleksei", "Ticket Number": "5552376681192"}],
  "Carrier": "Aeroflot", "Original Amount": "323.50", "Currency": "USD", "Issue Date": "2025-12-30",
  "PNR": "89GG62", "OTA Order ID": "", "Category": "Flight",
  "Vendor/App": "Aeroflot (direct airline sale)", "Comment": ""
}
```
- В `segments` только 7 перечисленных полей. `passengers` — список объектов, не строк.
- Нет вложений вида `"booking"`; нет полей USD/CAD и курсов валют. `Original Amount` + `Currency` — как напечатано в документе.
- `Vendor/App` — где куплен билет (Kupibilet, Trip.com, …), отличается от `Carrier` (фактический перевозчик; если рейс «выполняется авиакомпанией…» — указывается она).
- Несколько PNR / билетов / перевозчиков в одном документе — один JSON: PNR через `/`, номера билетов через `/`, `Carrier` через `/`, все сегменты в одном списке.
- Двойной PNR для одного сегмента (GDS + авиакомпания) — через `/` без пробелов.
- PNR «будет назначен» (агрегаторы) — вместо него номер заказа агрегатора.
- `Travel Date` (и желательно `Arrival Date`) никогда не пустая строка: пустая дата роняла `add_flight_v2` (`ValueError`). Неподтверждённая дата — соседняя известная, сомнение — в ответ в чате. `Time Depart`/`Time Arrival`/`Flight Number` могут быть пустыми.
- Путешествие, показанное только целиком (без номеров и времён пересадки): два сегмента по названной точке пересадки, подтверждённые времена — только на первом отправлении и последнем прибытии, остальное пусто.
- Скриншот начисления миль (нет билета): время из расписания только если несколько источников сходятся; иначе пусто.
- EMD (страховка и т.п.) в `Original Amount` не входит.
- Дубликат документа (тот же заказ, рейс, пассажиры) — новый JSON не делается, Alex сообщается.
- Многоязычные PDF (OZON.travel и т.п.): если просят «одна страница, English» — вынимается нужная страница в отдельный PDF. Несколько скриншотов одного заказа — один PDF; разных заказов — отдельные. Изображения всегда отдаются как PDF; присланный PDF не переупаковывается без просьбы.

## 4. Имена файлов `[T 01.11]`
`{YEAR}_{DD-MM}_{From}-{To}_{DD-MM}_{From}-{To}_..._{Passenger1}-{Passenger2}[-{PNR}].pdf`
- Год один раз в начале; даты сегментов DD-MM; города без пробелов, скобок, дефисов (апострофы и точки остаются: `Xi'an`, `St.Petersburg`).
- Имя пассажира в файле = точное написание в ячейке таблицы. Пассажиры без повторов, в порядке первого появления. PNR добавляется, если есть; два PNR — оба (`SSPTY/SC8SO9`).
- Бронь на границе лет: оригинал переименовывается под сегменты текущего года, для следующего года делается копия; ссылки в строках указывают на файл своего года; строки следующего года вручную переносятся в таблицу того года.
- Один PNR может иметь три отдельных файла (по одному на пассажира); имя каждого строится только из строк этого пассажира.
- Дубликаты в таблице определяются по пассажир+рейс+дата+время, не по PNR (авиакомпании повторно используют PNR в разные годы).

## 5. Исправленные ошибки (не вносить заново) `[T 01.11]`
1. Обрезание города до первого слова. 2. Сравнение дат строками. 3. Статус проверки то по-русски, то по-английски — теперь английский. 4. Дублирование файлов при многосегментной брони — теперь один файл на бронь. 5. Слияние рейсов по одному PNR — нельзя. 6. `SEGMENT_RE` разошёлся с форматом имён — любое изменение схемы имён синхронизируется в генераторе и разборщиках. 7. Турецкие İ/ı — нормализация до сравнения. 8. Даты без года в тексте документа принимаются по дню и месяцу. 9. `sortRange` ломается на текстовых датах — сортировка в Python. 10. Потеря гиперссылок при пересборке строк — `textFormatRuns` из `hyperlink`. 11. Сервисный аккаунт не может загружать файлы (нет квоты) — загрузка через OAuth реального пользователя. 12. Номер билета с `.0` — принудительно текст. 13. Расхождение имени файла и ссылки после ручной правки. 14. Ошибка рода в фамилии (Rodionov Alisa вместо Rodionova Alisa) — исправляется ячейка, не код. 15. `auditor_v2`: PNR с `/` — одинаковая нормализация строки и хвоста файла. 16. `rename_files`: проверка по префиксу года пропускала несовпавшее написание имени — теперь всегда сравнивается построенное имя с текущим. 17. `auditor_v2`: апостроф/точка в городе ломали `SEGMENT_RE` — `([A-Za-z'.]+)`. 18. `add_flight_v2`: не писался `Vendor/App`, `Comment` — исправлено (позже всё вошло в `flights.py`). 19. `rename_filesV2`: терялся второй PNR — собираются все. 20. `find_file_exact` ищет по всему Диску, а не в одной папке.
Рассинхрон «ячейка и реальное имя файла на Диске»: искать файл на Диске напрямую, поправить ячейку, затем переименование.
