# CLAUDE.md — инструкция для каждой сессии Claude в проекте «Перелёты» (family-flight-archive)

Этот файл Claude читает первым, до любого ответа Alex. Claude Code подгружает его сам, когда репозиторий подключён к сессии; если не подгрузился — прочитать вручную.
Создан 01.11.2026 по требованию Alex: один репозиторий = один проект, схема как у VPN (`virlab-infra`) и H&C: CLAUDE / STATE / FUTURE / HISTORY / START-PROMPT.

## 1. Что это за проект
- **Перелёты** — проверенная история перелётов семьи за 2016–2026: Rodionov Aleksei (Alexey), Rodionova Anna, Rodionova Alisa. Только эти трое.
- **Данные:** Google Таблицы `flights_{ГОД}_from_archive` (по одной на год) + PDF на Google Drive (папка «Flight Extraction 2016»). Идентификаторы — в `app/flights.py` (константы) и STATE.
- **Сайт:** https://archive.billup.cloud:8443 (nginx, пароль), каталог `/root/HC` на сервере, на который указывает DNS. Им пользуются консультанты по миграции и инспектор: **сайт не должен переставать работать**. Пароль в репозиторий не записывается.
- **Программа на ПК:** `app/flights.py` (один файл, меню; запуск из BAT). Папка на ПК Alex: `D:\Перелеты-2016-2026\FlightAuditor` (путь с кириллицей; в Git не лежит, копии файлов программы — в `app/`).
- **Решает только Alex.** Ответы по-русски, простыми словами. Данные (JSON, поля таблиц, имена файлов) — только по-английски, без кириллицы.
- **Связанные проекты (отдельные репозитории, не трогать отсюда):** VirLab VPN и серверы (`virlab-infra`, будущее имя `servers`) — на его сервере живёт сайт; H&C (`H-C-application`); Leader Machinery (`leader-machinery-na`).
- **Как выполняются действия.** У Claude нет доступа к ПК Alex, к серверам и к его Google-ключам. Файлы Claude готовит и отдаёт Alex; Alex кладёт их в папку на ПК и запускает сам. Claude читает Drive/таблицы только через подключения сессии.

## 4. Правила работы (полный текст — STATE раздел 3, при расхождении прав STATE)
**Данные:**
- Каждое поле JSON — строго из загруженного документа. Не выводить, не достраивать, не «подставлять по похожей поездке». Не показано в документе — поле пустое (кроме дат: `Travel Date` не бывает пустой).
- Один загруженный файл = один JSON, независимо от числа пассажиров, PNR и перевозчиков внутри.
- Режим по умолчанию: на присланный документ — только JSON (и PDF, если пришло изображение). Файлы, таблицы, пересборка архива — только по просьбе Alex.
- Кириллицы в данных нет (ни в каком поле).
- Имя пассажира: «Фамилия Имя», Title Case (`Rodionov Aleksei`); вариант написания имени (Aleksei/Alexey/Aleksey) — как в документе.

**Решения и изменения:**
- Claude ничего не меняет сам (программы, правила, меню, формулировки) без согласования: сначала предложение — что, зачем, чем грозит отказ. Есть сомнение, что изменение сломает план, — предупредить заранее.
- Ничего не удаляется: лишнее переносится в `_archive` на ПК.
- Дорогие операции (пересборка таблицы/архива, прогон нормализатора по годам) — сначала согласовать с Alex.
- Не задавать Alex вопросов, ответ на которые есть в STATE, репозитории, таблицах или на Drive (R-проверка перед вопросом).
- Слова «возможно», «вероятно», «видимо» в записях не используются; неизвестное — `[?]`.
- Метки источника: `[A дата]` — слова/решение Alex; `[V дата: как]` — проверено по документу, таблице, выводу; `[T дата]` — из пересказа прежних сессий, не проверено; `[?]` — неизвестно. Устаревшее не удаляется, а помечается `ЗАМЕНЕНО дата → …`.

**Сайт и сервер:**
- Любая команда для сервера — отдельным промптом с названием сервера и проверкой его IP (как в VPN-проекте). Серверные команды этой сессии не выдаются без согласования с VPN-сессией: сервером управляет проект VirLab.
- Публикация на сайт идёт только программой `flights.py` (v1.5+: по имени `archive.billup.cloud`, с проверкой сервера и папки `/root/HC`).

**Секреты (R15):**
- Не копировать в чат, отчёты и Git: `credentials.json`, `client_secret.json`, `upload_token.json`, `secrets/`, `.pem`, пароль сайта. Cursor их не читает. Все они закрыты в `.gitignore`.
- Если секрет оказался в присланном файле — не повторять его, сказать Alex.

**Записи:** каждое утверждённое изменение и решение — в STATE и журнал в том же ответе, затем `git pull --rebase`, commit, push. Ничего не остаётся «только в беседе».

## 5. Одна пишущая сессия
В репозиторий пишет только одна сессия — текущая рабочая. Когда Alex открыл новую по START-PROMPT, старая ничего не пишет. Перед каждой записью — `git pull --rebase`.

## 6. Когда сессия заполняется — передача
Признаки: сжатие контекста; Claude переспрашивает записанное; Alex говорит, что сессия «забилась». Claude сам предлагает передачу и выполняет «ЗАКРЫТИЕ СЕССИИ» из START-PROMPT.md. Правило заморозки STATE — как в `virlab-infra` (CLAUDE.md §6а): когда STATE больше 150 КБ, замороженное уходит в `archive/` с индексом `archive/INDEX.md`.
